# Swarm v0.1.1: Maintenance & Linux Rendering Stability Release

**Swarm v0.1.1** is a stability and bug-fix release addressing Linux WebKitGTK rendering glitches, enabling release devtools diagnostics, and isolating the wallpaper subsystem exclusively to high-performance static image assets.

---

## 🛠️ Key Fixes & Improvements in v0.1.1

### 1. Fix Linux Production AppImage Black Screen (WebKitGTK Compositing Fallback)
- **Problem**: When running the packaged `.AppImage` on Linux (particularly on Arch Linux, Fedora, Ubuntu, and Debian under Wayland or Mesa/DRI3 graphic stacks), WebKitGTK attempted hardware-accelerated texture compositing through EGL/DMABuf, resulting in an unresponsive black or blank window viewport.
- **Resolution**:
  - Configured native single-threaded process initialization in `src-tauri/src/main.rs` and `src-tauri/src/lib.rs` to automatically enforce `WEBKIT_DISABLE_COMPOSITING_MODE=1` and `WEBKIT_DISABLE_DMABUF_RENDERER=1` when running on Linux.
  - WebKitGTK now gracefully uses stable 2D surface rendering on all Linux desktop environments (Wayland, XWayland, X11, Mesa, Intel, AMD, and NVIDIA), guaranteeing immediate and reliable UI rendering upon launch.

### 2. Enabled DevTools in Release Builds
- Configured Tauri's `"devtools"` feature across `Cargo.toml` and `tauri.conf.json`.
- Developers and contributors can now right-click anywhere in the release window and choose **Inspect Element** to view the live DOM, inspect stylesheets, and diagnose console logs directly in production builds.

### 3. Wallpaper Engine: Exclusively Static Image Uploads
- Restricted wallpaper file pickers to static image formats (`image/png, image/jpeg, image/webp, image/svg+xml`).
- Completely removed legacy video decoding pipelines (`.mp4`, `.webm`, `.mov`), background `<video>` elements, and video thumbnail listeners to eliminate GStreamer pipeline leaks, excessive memory consumption, and video playback crashes on Linux.
- Retained dominant accent extraction directly from loaded image elements.
