# PandaCode 0.2.46

- **Cloud sandboxes for agents.** Connect providers in Settings → Agents → Cloud sandboxes, and their machines join the VM panel and the agent VM tools beside local VMs:
  - **Daytona**: Linux desktops agents can see, click and type into, and run commands in. They stop after 15 idle minutes.
  - **Cloudflare**: container sandboxes in your own account for commands. PandaCode deploys a small Worker once (needs Docker running and a Workers Paid plan), protected by a random token kept in your keychain; containers stop after 10 idle minutes.
  - **AWS**: Ubuntu and Windows Server desktops on EC2 in your account, using your AWS CLI sign-in. They have no open ports: commands and the screen go through Systems Manager (screens need the Session Manager plugin). Also AWS AgentCore code interpreter sessions for quick commands.
- **Deploy with an agent.** A new Deploy button in the header starts a task that ships the project to Vercel, Cloudflare or AWS end to end: it builds, deploys a preview, checks the live URL, then goes to production and reports what changed. Agents run the Vercel, Wrangler and AWS CLIs through one approval-gated tool that is already signed in, so tokens never reach their prompts and are scrubbed from output.
- Keys for Daytona, Cloudflare and Vercel are stored in the OS keychain; AWS uses your existing CLI login.

Known limitations: cloud machines and deploys cost money in your accounts; agents are told to ask before creating paid resources, and every create or deploy asks for approval. Windows desktops take about 10 minutes to set up on first boot. These integrations were tested against each service's published API with simulated responses; first use with real accounts may surface rough edges, so please report them.

This is an Alpha preview. macOS uses ad-hoc signing without Apple notarization;
Windows does not yet have Authenticode signing. All platform updates retain
cryptographic signature verification. Linux requires X11/XWayland.
