# Swarm — working notes

## Project and releases
- Swarm is open source (the MIT-based Swarm License in `LICENSE`, which requires forks to credit Swarm and PandaCode) with no accounts, license checks or telemetry; keep it that way. Never add code that phones home, and never commit secrets or personal paths.
- Swarm v0.1.0 is built on and forked from [PandaCode v0.3.16](https://github.com/aicodeking/pandacode).
- Follow [docs/releasing.md](docs/releasing.md) for shipping: `npm run release:version X.Y.Z`, write `releases/X.Y.Z.md`, push tag `vX.Y.Z`. `.github/workflows/release.yml` builds macOS (Apple silicon), Windows x64 and Linux x64 and attaches them to a GitHub Release; signing is optional. Only release when the user asks.
- Contributor setup and PR process: [CONTRIBUTING.md](CONTRIBUTING.md). CI is `.github/workflows/ci.yml`.

## Verify
- `npx tsc --noEmit` — typecheck (also runs inside `npm run build`).
- `npm test` — Node unit tests (`tests/*.test.mjs`).
- `node --test tests/ultracode.test.mjs` — ULTRACODE orchestration unit tests.
- `node --test tests/vibe_suite.test.mjs` — Vibe Time-Machine, Sketch, and Canvas tests.
- `npm run test:release` — release script tests (`scripts/release/*.test.mjs`).
- `npm run test:rust` — Cargo test suite (`cargo test --locked --manifest-path src-tauri/Cargo.toml --lib`).
- `cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings` — strict Rust lints.
- `npx playwright test` — browser suite against the Vite preview (`npm run dev` on 127.0.0.1:1420 is started/reused automatically; needs Google Chrome at `/Applications/Google Chrome.app`). Full run ≈ 3.5 min at the default 4 workers (`PW_WORKERS=N` overrides); pass file paths or `-g "title"` for a subset.
- `npx playwright test -c playwright.webkit.config.ts` — the same suite in WebKit (the real target is WKWebView).

## Swarm v0.1.0 Architecture & Modules

### Rust Core Architecture (`src-tauri/src/`)
- `ultra_engine.rs`: ULTRACODE multi-agent orchestration engine. Features architect reconnaissance turn (`solo_deep` vs `parallel_swarm`), dynamic work decomposition, locked semantic interface contracts, concurrent execution in dedicated git worktrees (`.git/ultra_worktrees/`), localized lints, global integration validation, and critic escalation patch merges.
- `arena.rs`: Dual-harness 2x race execution engine. Manages side-by-side prompt execution across two different agent harnesses, real-time telemetry streaming (TTFT, throughput, duration, diff sizes), and winner branch promotion into the primary working tree.
- `design_canvas.rs`: File management, artboard enumeration, and DOM/AST synchronization for visual design artboards stored in `.swarm/design/`.
- `vibe_time_machine.rs`: Turn-level Git-backed snapshot creation, instant zero-risk rollback, and task branch forking.
- `agent_tools.rs`: Managed Swarm terminal and browser tools exposed to coding agents.
- `overlay.rs`: Quick launcher window management and system tray integration.
- `bots/*`: Native bot channels (Telegram, Discord, Slack, WhatsApp, HTTP/Web).
- `cloud/*`: Daytona, Cloudflare Workers, AWS SSM, and deploy runners.
- `vm/*`: Local Tart VM driver and VNC RFB frame streaming on Apple silicon.

### TypeScript Frontend Architecture (`src/`)
- `ultracode.ts`: Orchestration state controller for ULTRACODE multi-agent swarms, phase tracking (`recon`, `foundation`, `subtasks`, `critic`, `merge`), and progress rendering.
- `arena.ts` & `arena.css`: Dual-harness Arena UI, live telemetry comparison graphs, split diff view, and winning candidate selection.
- `design-canvas.ts` & `design-canvas.css`: 3-column Design Canvas workspace featuring DOM Layers Tree, pannable/zoomable multi-device viewports (Desktop, iPhone 16 Pro, iPad, custom), live CSS Properties Inspector, AI REMIX prompt bar, and one-click artboard component compilation.
- `vibe-time-machine.ts`: Visual timeline, turn snapshot inspection, instant rollback, and branch forking controls.
- `live-sketch.ts` & `live-artifacts.ts`: Sketch-Over-Live-Preview annotation canvas overlay, screenshot coordinate packaging, and live preview rendering.
- `voice-vibe.ts`: Push-to-Talk audio capture and real-time reactive Web Audio frequency waveform visualizer.
- `auto-heal.ts`: Automated live runtime error interception, stack formatting, and agent self-healing dispatch loop.
- `token-saver.ts`: Per-task response-style packs (Caveman Lite/Full/Ultra, Lean code, Quiet tools, RTK) saving 40%–70% output tokens.

### Workspace & Branding Conventions
- **Design Artboards**: Stored in `.swarm/design/` inside the project root (ignored by Git via `.gitignore`).
- **Standalone Chats**: Quick scratchpad tasks outside repositories live in `~/Swarm Chats`.
- **Visual Assets**: Active application background uses `public/honeycombs.svg` (`/honeycombs.svg`). Official application icons reside in `public/icon.png` (512×512) and `src-tauri/icons/` (`icon.ico`, `icon.icns`, `icon.png`, `32x32.png`, `128x128.png`, `128x128@2x.png`).

## UI conventions
- Color: never write a literal accent color. Use `--accent`, `--accent-rgb` (for `rgb(var(--accent-rgb) / a)`), `--on-accent` (text on accent fills), `--accent-dim`/`--accent-ink`, `--focus`, `--accent-hover`, `--accent-tint`. `src/palette.ts` sets them from the user's choice (wallpaper accent from `src/wallpaper-accents.ts`, classic yellow, a swatch) or from an imported VS Code theme (`html[data-vsix]`, mapped in `src/palette-core.ts`), which also sets the surface tokens and holds still when wallpapers change. Themes are imported natively by `vsix_themes.rs` (colors only, nothing executed). Regenerate `wallpaper-accents.ts` when scenes change; `tests/palette.test.mjs` checks every scene and 23 recorded real themes for contrast.
- Material: every floating surface (dialog plate, menus, toast) is one warm glass defined by the `--glass-*` tokens in `src/motion.css`; a yellow highlight sits at the top edge. Reduced transparency/contrast rules must keep solid fallbacks.
- Motion: Swarm is instant. `MOTION = false` in `src/motion.ts` turns off every spring, entrance and exit (each caller has an instant path), and a global `transition:none!important` (end of `styles.css` and `overlay.css`) removes CSS transitions. Only looping status animations (spinners, working pulses) run. Press feedback uses the `scale` property, never `transform`, so a button positioned with `transform` stays under the pointer while pressed.
- The `<dialog>` stays transparent and untransformed: `.dialog-plate` behind it carries the glass, `.dialog-scrim` dims, and a closed-shadow-root ghost carries the exit. Never put `backdrop-filter`/`transform` on the dialog itself — menus opened inside it are `position: fixed` in viewport coordinates.
- Menu triggers (`aria-haspopup`, pickers) keep `--press: 1`; a pressed-scale on an anchor shifts the popover it positions.
- Segmented controls (`.view-switch`, `.inspector-tabs`, `.settings-tabs`) hand their highlight to `.segment-thumb` via `trackSegment()`.
- Swarm updates itself from GitHub Releases: `src/app-updates.ts` (checks at launch and every 6 h, downloads in the background, installs with a restart only when no agent runs and the user has been idle; decisions in `src/app-updates-policy.ts`), the status-bar `#update-status` button, and Settings → About. Tauri's updater verifies each download against the public key in `tauri.conf.json`; releases carry signed update files and `latest.json` (`scripts/release/updater-manifest.mjs`). This is the only check of Swarm's own; list any new automatic request in the README privacy table and the website privacy page.
- The GitHub view (`state.view === 'github'`, header button beside Board, hidden while `githubEnabled()` is false) is `src/github-hub.ts` with `src/github-hub.css`, mounted lazily by `syncGithubHub()` in `main.ts` into `#github-hub`; full-width like the board (layout rules in `styles.css`). Native side `src-tauri/src/github_hub.rs` (`github_repos`, `github_repo_pulls`, `github_repo_issues` by `owner/name`; `github_project_repos` maps projects by `origin` remote; `github_clone_repo`). Agent prompts and thread titles are in `src/github-hub-prompts.ts` and mention `#123`, so `github.contextFor` attaches the item; `startHubTask()` in `main.ts` creates, links, titles and (optionally) sends the task. Preview data: `src/preview-github-hub.ts`.
- Branch/worktree UI lives in `src/worktrees.ts` (context bar, `#branch-chip` menu, dialogs, cleanup offer); GitHub in `src/github.ts`; a task's linked PR renders as the inspector's PR tab from `src/github-pull.ts` (native side `github_pull.rs`), and after every run end `github_detect_pull_request` links a PR URL the turn mentioned when it is on the checkout's branch or was created during the turn (an open link is never replaced). Both receive callbacks from `main.ts` instead of importing its state. `linkChip()` and every GitHub affordance return nothing while `githubEnabled()` is false.
- Local VMs (Apple silicon): `src-tauri/src/vm*` drives Tart (`vm/tart.rs`; one-click install of the notarized release in `vm/setup.rs`, team `9M2P8L4D89`) on Virtualization.framework. VMs run headless with `--vnc-experimental`; `vm/rfb.rs` is a small RFB client (that server answers only when the screen changed, so captures are incremental with a quiet window) and `vm/screen.rs` maps clicks, drags, scrolls, typing and key combos, scaling screenshots to 1280 px wide. Commands run through `tart exec` (Tart Guest Agent, no SSH). New VMs start right away, and a Linux VM without a desktop gets one in the background whenever Swarm starts it (`vm/desktop.rs`). The panel draws frames on a canvas: the app CSP allows no `blob:` images, and `tests/vm.spec.ts` runs under that CSP. Linux guests start at 2 GB; idle VMs are suspended (macOS) or stopped (Linux) after `vm::IDLE`, and on quit. Agents get `pandacode_vm_*` tools (`vm/tools.rs`); the inspector's VM tab is `src/vm-panel.ts`, mocked in `src/preview-vm.ts`. Live tests are `#[ignore]`d and take `PANDACODE_VM`/`PANDACODE_VNC`.
- Cloud sandboxes and deploys live in `src-tauri/src/cloud*`. Machine IDs are `provider:native-id` (`daytona:`, `cloudflare:`, `aws:`, `agentcore:`), so the `pandacode_vm_*` tools and the VM panel route by prefix (`cloud::split`). Keys are in the OS keychain via `secret_store.rs` (shared with bots) under `app.pandacode.cloud`; non-secret settings are one JSON value beside them (`cloud::Settings`). Daytona is REST (`cloud/daytona.rs`, toolbox computer use). Cloudflare deploys `cloud/cloudflare_worker/` (Sandbox SDK 1.0 container Worker, bearer token, 10 min idle) with Wrangler; Cloudflare cannot list Durable Objects, so `cloudflare_sandboxes` remembers names. AWS uses the user's AWS CLI login: EC2 desktops via SSM only (no inbound ports; VNC on the instance's localhost, carried by an SSM port-forward in `cloud/aws_screen.rs`), and AgentCore code interpreters (`cloud/agentcore.rs` signs InvokeCodeInterpreter with SigV4 and reads the event stream). Deploys: `pandacode_cloud_cli` (`cloud/deploy.rs`, approval-gated) runs vercel, wrangler, railway, aws or gcloud in the checkout with credentials only in that process's environment and scrubbed from output; the header Deploy menu (`src/deploy.ts`) starts a task with a platform brief. Settings → Agents → Cloud sandboxes is `src/cloud-settings.ts`; preview mocks are in `src/preview-vm.ts`. HTTP tests use `cloud::http::mock`.
- Teams: the composer's Team button toggles an automatic team (`toggleTeam` in `main.ts`, `config.auto`), or, with Settings → Agents → Classic team setup (`src/team-mode.ts`, a per-window preference), opens the Architect & workers setup. Named agent teams (`src/agent-teams.ts` in Settings) are team profiles with `config.rosterOnly` and `config.name`; the model picker lists them under Agent teams, picking one calls `architect_configure` with the profile, and picking a plain model removes it. Natively, `staff_from_roster` in `architect.rs` refuses any worker model outside a roster-only team.
- Prompt attachments (images, documents, folders, sketches) live in `src/attachments.ts`; the mockup editor in `src/sketch.ts` is lazy-loaded from the `+` menu. Images ride the existing `imageIds` pipeline (`browser-captures/<uuid>.png`, four per message including screenshots); documents and folders become `Document context:` / `Folder context:` blocks. Sent context folds behind `.message-context` in user messages — extend `CONTEXT_BOUNDARY` in `main.ts` when adding a new block type.
- Thread switching draws in one frame: `selectSession` shows the thread's remembered page (`threadPages` in `main.ts`, only pages whose messages belong to that thread) and redraws after the refresh only if the page changed; `markdown()` in `dom.ts` reuses formatted HTML by source text, so nothing reflows from raw text. The sidebar updates with `morph()` (`dom.ts`), which keeps unchanged rows and replaces any element whose `id`/`data-id` changed, so a click never lands on a row that changed task underneath it.
- Find in thread (⌘F, `src/thread-find.ts`): matches in user and agent message text are painted with the CSS Custom Highlight API (`thread-find`, `thread-find-current`), never by rewriting the DOM; a MutationObserver re-runs the query as the transcript changes, and the current match opens any folded turn around it. ⌘G/⇧⌘G and Enter/⇧Enter step; Esc closes without stopping a running agent.
- Agent questions (`src/agent-input.ts`) render rich Markdown through `src/rich-markdown.ts`: header, question and option text are Markdown; `![alt](path)` loads a workspace image as a data: URL via `workspace_image` (task-scoped, image types, 8 MB); remote images become links and are never fetched; ```chart JSON (bar/line/pie) is drawn as SVG; ```svg is sanitized; ```html is sanitized static HTML in a shadow root (no scripts, forms, frames or non-inline images). The app CSP is unchanged. `RICH_QUESTIONS` in `lib.rs` tells agents about it through the cached app instructions.
- Menus and dialogs are one line per row. Choice-menu items show a detail beside the label only when label + detail fit (`BRIEF_ROW` in `choice-menu.ts`); longer details, long `.dialog-description`s (`LONG_DESCRIPTION` in `main.ts`), static `.field-help` hints, and long setting-row `small`s move behind an `infoMark()` (`src/tooltip.ts`) whose text is still in the DOM as `.sr-only`. Live hints opt out with `data-live`; live status `small`s keep a class and stay inline. Never nest a mark inside a `<label>`/`<h2>` — it would join the field's accessible name.
- Overlays mounted inside the open dialog (`.floating-menu`, `.tip-bubble`) are ignored by the dialog motion observer; add new overlay classes there if they mount into `#dialog`.
- Anything rendered by the composer must be styled from an always-loaded stylesheet: `architect.css` (and other lazily imported CSS) only arrives with its module, which is how the Team button once changed size on first click.
- Native: `workspace::run_process` is the one bounded runner for external tools (`git`, `gh`); user text goes to `gh` as `--flag=value`.
- Turn speed and tokens: the fixed app instructions (sidebar titles, `pandacode-run.sh`, change tracking; `app_instructions()` in `lib.rs`) go to Claude-family harnesses once as `--append-system-prompt`, which caches with the prefix; other harnesses get them in the message on a new conversation and every 8th turn. Only a one-line current-title note rides each message. After a successful Claude turn, `providers/warm.rs` starts the next turn's process in the background (at most 2, 10 idle minutes); a follow-up adopts it only when model, mode, effort, folder, resume ID, instructions and tool catalog all match (the MCP server is rebound to the new turn at the same address), so it skips the CLI's startup. Anything else starts cold.
- Harnesses: adding a provider means touching every `"kimi" | "opencode" | "antigravity"`-style match in `providers.rs`/`acp.rs`, the allowlists in `storage.rs`, `overlay.rs`, `architect*.rs`, `terminal.rs`, `slash_commands*.rs`, `provider_settings.rs`, plus `ProviderId` and its `Record` maps on the frontend (tsc flags the maps). ACP harnesses share `acp.rs`; provider quirks (Grok's `authenticate` step, plan-mode policy, `_meta.totalTokens` usage) live behind `config.provider` checks there. Record real frames in the tests, and keep an ignored live smoke test per installed CLI. Key-based Claude Code relays (GLM, MiMo) each get a `providers/<id>.rs` with `environment()/arguments()/configure()/models()`, a `Credential` in `provider_settings.rs` (own secure-store account + env var), and an entry in the `keyed` table of `src/provider-settings.ts`, which renders the card's key form and status. Schema is at `user_version` 25 (the bot tables in `bots::SCHEMA`; version 24 added `sessions.limited_at`, `limited_until` and `resume_at_reset`; version 23 `queued_messages`, the durable per-task queue in `message_queue.rs`; version 22 added `sessions.draft`, set for a New task until its first saved prompt publishes it; version 21 added `sessions.pinned` and `sessions.sidebar_order`, version 20 `sessions.title_origin`, version 19 `sessions.last_prompt_at`). Drafts are excluded from `list_sessions`; empty ones are deleted on leave (`discard_draft`) and at startup. Adding a migration step means bumping `storage::SCHEMA_VERSION` (the outer guard reads it; a test checks it matches the newest `PRAGMA user_version=`) and updating the tests that assert the number.
- Queue and steering: while an agent runs, Enter queues (`queue_*` commands, shown by `src/message-queue.ts` above the composer) and ⌘/Ctrl Enter steers (`steer_task` → `RunInput::Steer`, `providers/steering.rs`). Claude-family harnesses steer on stream input (launched with `--replay-user-messages` so a late steer keeps the run open for its turn); Codex uses `turn/steer`; others queue. A clean run end delivers the next entry; a failure, stop or restart holds the queue until Resume. The prompt stays enabled during runs, so `renderComposer` must keep focus and the caret. The wider roadmap is in `docs/parity-plan.md`.
- Bots (docs/bots.md) live in `src-tauri/src/bots*` and `src/bots*.ts`. Each bot owns a workspace project and each conversation is an ordinary task, so `run_finished`/`approval_requested` hooks in `lib.rs` route replies and approvals back to channels. Bots are listed in the sidebar's Bots section (`renderBots` in `main.ts`, from `bots_list`, which includes each bot's `desktopSession`); a row opens that conversation via `bot_desktop_thread` in the ordinary conversation pane: the same transcript, streaming, composer and model picker as any task (a model chosen there is saved on that conversation with `configure_session`; the bot's profile model applies to new conversations). `botForThread()` in `main.ts` finds the bot for any thread in its workspace, so the header shows `botCrumb()` (name, state, pause, Settings), an empty thread shows `botWelcome()`, the prompt reads "Message <bot>…", and the `.bot-thread` class hides the project bar; these styles live in `styles.css` because they render before the bots module loads. Settings are a modal (`showBotSettings`, `mountBots` with `layout: 'settings'`): Profile, Conversations, Memory, Schedules, Channels, Rules and Activity, styled by `src/bots-settings.css`; the Bots window (`layout: 'window'`) is the same body beside a bot list and creates bots, which then open in their conversation. There is no separate bot chat view. Prompts typed in a bot's own conversation go through `bot_message` so the brief and memories apply; the brief folds behind the message's attached context. Bot workspaces stay out of the project tree, filter and picker (`userProjects()`). Bot tasks drain their queue natively; the window skips `dispatchQueue` for bot projects. Channel secrets stay in the keychain via `bots/secrets.rs` and never reach the webview. The local server (`bots/channels/http.rs`) binds 127.0.0.1 only and checks the Host header for web chat.
- Markdown everywhere (transcript, streaming, subagents, team workers, launcher, bot chat) goes through `markdownHtml()` in `src/dom.ts`, which uses Software Mansion's Enriched Markdown engine: the md4c WebAssembly parser vendored in `src/vendor/enriched-markdown/` (see its README for provenance and updating) and the renderer in `src/enriched-markdown.ts`. Output is sanitized by DOMPurify, then math placeholders are typeset by KaTeX (`src/math.ts`, lazy). `marked` remains only as a fallback if the WebAssembly cannot start. The app CSP therefore includes `'wasm-unsafe-eval'` (never plain `'unsafe-eval'`; `tests/bundle.test.mjs` guards both), and the bots web chat page loads the same parser from the local server at `/assets/md4c.js`. New Markdown elements need styles in `styles.css` (`.md-*` classes).
- Browser preview mocks for new IPC commands live in `src/preview.ts` (`previewWorktree`, `previewGithub`); add one for every new command so the Playwright suites can cover it.
